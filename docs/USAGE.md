# Usage Guide

This guide covers the `jl-forge` commands, the Python API behind them, and a complete build script.

## Installation

```bash
pip install jl-forge          # CLI and Python API
pip install 'jl-forge[xeus]'  # adds jupyterlite-xeus, for the default xeus-env mode
```

`jupyter lite build` itself comes from `jupyterlite-core` plus a kernel package (`jupyterlite-xeus` or `jupyterlite-pyodide-kernel`), which your build installs. micromamba is required for xeus-python environments.

## Commands

### `jl-forge clean WORKSPACE [--root ROOT]`

Deletes and recreates `WORKSPACE`. It refuses when `WORKSPACE` is not strictly inside `ROOT` (default: the current directory), or when it contains `.git` or `pyproject.toml`.

```bash
jl-forge clean workspace
```

### `jl-forge notebooks DIR [--strip] [--prepend LINE | --pyodide-install]`

Rewrites every `DIR/*.ipynb` in place:

- `--strip` clears `outputs` and `execution_count` of code cells and removes saved widget state. Markdown cells are untouched.
- `--prepend LINE` adds `LINE` at the top of the first code cell, unless it is already there, so repeated builds don't duplicate it.
- `--pyodide-install` prepends `from install import _; await _()`, the call to the script generated by `pyodide-install`.

```bash
jl-forge notebooks workspace/content --strip --pyodide-install
```

### `jl-forge xeus-env --root-prefix DIR --pyproject FILE [options]`

Creates an emscripten-wasm32 conda environment at `DIR/envs/xeus-kernels`, for `--XeusAddon.prefix`. Packages are `xeus-python`, `xeus-python-shell`, `xeus-python-shell-lite` and the project's dependencies.

| Option | Effect |
|:-------|:-------|
| `--extras A B` | Add `[project.optional-dependencies]` groups; unknown extras only warn |
| `--exclude A B` | Leave packages out |
| `--micromamba` | Call micromamba directly instead of `jupyterlite_xeus.create_conda_env` |
| `--verbose` | Pass `-vvv` to micromamba (with `--micromamba`) |

Channels are conda-forge and emscripten-forge-dev.

### `jl-forge xeus-mount SOURCE --prefix PREFIX`

Prints a `--XeusAddon.mounts` value that mounts the `SOURCE` package directory into the kernel's site-packages:

```bash
$ jl-forge xeus-mount src/mypkg --prefix workspace/xeus/envs/xeus-kernels
/abs/path/src/mypkg:/lib/python3.13/site-packages/mypkg
```

The Python version comes from the prefix, so it can't drift from the created environment.

### `jl-forge pyodide-install --pyproject FILE --package-name NAME --wheel-dir DIR [options]`

Writes `DIR/install.py`, which installs the project wheel and its dependencies with piplite:

```python
import piplite
async def _():
  packages = ['emfs:mypkg-0.1.0-py3-none-any.whl', 'packaging>=23']
  await piplite.install(packages, keep_going=True)
```

`DIR` must contain exactly one wheel for `NAME`, and `install.py` sits next to it so the `emfs:` URL resolves. `--extras` and `--exclude` work as for `xeus-env`; exclude packages Pyodide replaces, such as `aiohttp`.

### `jl-forge urls PUBLIC [--port PORT]`

Prints the command serving `PUBLIC` locally, then a URL for each notebook of each site found in `PUBLIC` (the directory itself or its subdirectories containing `jupyter-lite.json`), per app built: `lab`, `notebooks`, and Voici render pages when present.

```bash
$ jl-forge urls workspace/public
Serve: python -m http.server 8000 --directory workspace/public
http://localhost:8000/
http://localhost:8000/pyodide/lab/index.html?path=demo.ipynb
http://localhost:8000/xeus/lab/index.html?path=demo.ipynb
...
```

## Dependency Handling

Both kernels read the same `pyproject.toml`:

- Names are normalized (`My_Pkg` → `my-pkg`).
- A package listed several times keeps the intersection of its constraints: `tqdm>=4` and `tqdm<5` become `tqdm<5,>=4`.
- Environment markers are evaluated for the browser (`sys_platform == "emscripten"`), so `pywin32; sys_platform == "win32"` is dropped.
- Requirement extras (`pkg[extra]`) are dropped; conda and piplite don't resolve them.

Specs are passed unchanged to conda and piplite. Use constraints both understand: `==`, `>=`, `<`, `!=`.

## Python API

```python
from pathlib import Path
from jl_forge import dependencies, notebooks, pyodide, xeus

project = dependencies.load_project(Path("pyproject.toml"))
specs = dependencies.to_specs(dependencies.collect_requirements(project, extras=["lab"], baseline=xeus.XEUS_RUNTIME))

prefix = xeus.create_env(Path("workspace/xeus"), specs, micromamba=True)
mounts = xeus.mount(Path("src/mypkg"), prefix)

nb = notebooks.read(Path("demo.ipynb"))
notebooks.prepend_to_first_code_cell(notebooks.strip(nb), pyodide.INSTALL_LINE)
notebooks.write(Path("demo.ipynb"), nb)
```

`jl_forge.cli.reset_workspace(workspace, root)` and `jl_forge.cli.site_urls(public, base_url)` are the functions behind `clean` and `urls`.

## Complete Build Script

[`examples/demo/build.sh`](../examples/demo/build.sh) builds both sites from one project. Its outline:

```bash
jl-forge clean workspace

# xeus-python, from a venv with jupyterlite-core + jupyterlite-xeus
jl-forge notebooks workspace/content-xeus --strip
jl-forge xeus-env --micromamba --root-prefix workspace/xeus-root --pyproject pyproject.toml
jupyter lite build --contents "$PWD/workspace/content-xeus" --output-dir workspace/public/xeus \
  --XeusAddon.prefix=workspace/xeus-root/envs/xeus-kernels \
  --XeusAddon.mount_jupyterlite_content=True \
  --XeusAddon.mounts="$(jl-forge xeus-mount src/mypkg --prefix workspace/xeus-root/envs/xeus-kernels)"

# Pyodide, from a venv with jupyterlite-core + jupyterlite-pyodide-kernel
uv build --wheel --out-dir workspace/content-pyodide .
jl-forge pyodide-install --pyproject pyproject.toml --package-name mypkg --wheel-dir workspace/content-pyodide
jl-forge notebooks workspace/content-pyodide --strip --pyodide-install
jupyter lite build --contents "$PWD/workspace/content-pyodide" --output-dir workspace/public/pyodide

jl-forge urls workspace/public
```

Application-specific steps (credentials, model files) stay in your script.

## Voici Dashboards

[Voici](https://github.com/voila-dashboards/voici) renders each notebook as a dashboard page, `voici/render/<notebook>.html`, executed in the browser by the site's kernel. jl-forge needs nothing specific; enable it in the `jupyter lite build` step:

1. Install `voici-core` in the build venv, next to the kernel package.
2. List the apps explicitly. Voici is not built by default, and `--apps` replaces the defaults:
   ```bash
   jupyter lite build --apps lab --apps notebooks --apps tree --apps voici ...
   ```
   The `[static] app 'voici' is not one of: ...` warning is harmless.

`jl-forge urls` lists the Voici pages it finds.

Voici constrains package versions, notably for the Pyodide kernel and for widgets; see [Apps, Kernels & Version Constraints](COMPATIBILITY.md).
