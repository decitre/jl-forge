# Usage Guide

This guide covers the `jl-forge` commands, the Python API behind them, what stays compatible across releases, and a complete build script.

## Installation

```bash
pip install 'jl-forge[pyodide]' jupyterlite-core jupyterlite-pyodide-kernel   # Pyodide site (the extra adds uv)
pip install 'jl-forge[xeus]' jupyterlite-core                      # xeus-python site (adds jupyterlite-xeus)
```

Install jl-forge in the build environment, next to `jupyterlite-core` and the kernel, not with `pipx` or `uv tool`: `pyodide-dist` reads the Pyodide version from the installed kernel, and `xeus-env` and `xeus-pack-config` import jupyterlite-xeus and empack. In a uv project, `uv add --dev jl-forge` does it. Building both sites needs one environment per kernel; see [RUNTIME.md](RUNTIME.md). micromamba is required for xeus-python environments.

`pyproject.toml` only needs `[project.dependencies]`; a `[build-system]` and a package are needed only for `pyodide-install` and `xeus-mount`, when notebooks import your own package.

## Commands

### `jl-forge clean WORKSPACE [--root ROOT]`

Deletes and recreates `WORKSPACE`. It refuses when `WORKSPACE` is not strictly inside `ROOT` (default: the current directory), or when it contains `.git` or `pyproject.toml`.

```bash
jl-forge clean workspace
```

### `jl-forge notebooks DIR [--strip] [--prepend LINE | --pyodide-install]`

Rewrites every notebook in `DIR` and its subdirectories in place (`.ipynb_checkpoints` excluded):

- `--strip` clears `outputs` and `execution_count` of code cells and removes saved widget state. Markdown cells are untouched.
- `--prepend LINE` adds `LINE` at the top of the first code cell, unless it is already there, so repeated builds don't duplicate it.
- `--pyodide-install` prepends `import sys; sys.path.append("/drive"); from install import _; await _()`, the call to the script generated by `pyodide-install`. `/drive` is the contents root in the Pyodide kernel, so notebooks in subdirectories use the `install.py` at the root; one in the notebook's own directory comes first.

```bash
jl-forge notebooks workspace/content --strip --pyodide-install
```

### `jl-forge xeus-env (--root-prefix DIR | --cache-dir DIR) --pyproject FILE [options]`

Creates an emscripten-wasm32 conda environment for `--XeusAddon.prefix`, and prints its path as the only line on stdout. Packages are `xeus-python`, `xeus-python-shell`, `xeus-python-shell-lite` and the project's dependencies.

- `--root-prefix DIR` creates it at `DIR/envs/xeus-kernels`, every time.
- `--cache-dir DIR` creates it once and reuses it while the specs and channels stay the same, skipping the solve and download (minutes). Each set of specs gets its own `DIR/<hash>/envs/xeus-kernels`; downloaded packages are shared in `DIR/pkgs`. Unpinned specs aren't refreshed while cached: delete the directory to pick up new releases.

```bash
XEUS_PREFIX=$(jl-forge xeus-env --micromamba --cache-dir ~/.cache/jl-forge/xeus --pyproject pyproject.toml)
```

| Option | Effect |
|:-------|:-------|
| `--extras A B` | Add `[project.optional-dependencies]` groups; unknown extras only warn |
| `--exclude A B` | Leave packages out |
| `--micromamba` | Call micromamba directly instead of `jupyterlite_xeus.create_conda_env` |
| `--verbose` | Pass `-vvv` to micromamba (with `--micromamba`) |

Channels are conda-forge and emscripten-forge-4x.

### `jl-forge xeus-pack-config --out FILE`

Writes empack's default packing config plus exclusions of files a browser kernel never uses, and prints the file's absolute path, for `--XeusAddon.empack_config`:

- `lib/libpython*.a` and `include/`: the static library and C headers, for building, not running;
- `tkinter`: there is no Tk in a browser;
- jedi's type stubs of non-standard-library packages (typeshed `stubs/`, `django-stubs`); the standard library stubs stay for completion;
- `*.dist-info/RECORD` files, only used to uninstall.

It halves the packed environment of the demo (13 MB to 6.3 MB). Run it in the xeus build venv: it reads the default config of the installed empack.

### `jl-forge xeus-mount SOURCE --prefix PREFIX`

Prints a `--XeusAddon.mounts` value that mounts the `SOURCE` package directory into the kernel's site-packages. Only needed when notebooks import the project's own package:

```bash
$ jl-forge xeus-mount src/mypkg --prefix workspace/xeus/envs/xeus-kernels
/abs/path/src/mypkg:/lib/python3.13/site-packages/mypkg
```

The Python version comes from the prefix, so it can't drift from the created environment. Don't write the `/lib/python3.13/site-packages/...` path by hand in `--XeusAddon.mounts`: it breaks when the environment's Python changes.

### `jl-forge pyodide-install --pyproject FILE --package-name NAME --wheel-dir DIR [options]`

Writes `DIR/install.py`, which installs the project wheel and its dependencies with piplite. Only needed when notebooks import the project's own package; without it, skip `notebooks --pyodide-install` too:

```python
import piplite
...
async def _():
  emfs_wheels = [f'emfs:{Path(__file__).parent / w}' for w in ['mypkg-0.1.0-py3-none-any.whl', 'dep_a-1.0-py3-none-any.whl']]
  for wheel in emfs_wheels:
    await piplite.install(wheel, deps=False, keep_going=True)
  packages = [spec for name, spec in {'packaging': 'packaging>=23'}.items() if not _installed(name)]
  if packages:
    await piplite.install(packages, keep_going=True)
```

`DIR` must contain exactly one wheel for `NAME`; `install.py` sits next to it and installs it by absolute `emfs:` path. Make `DIR` the contents root: notebooks in any subdirectory then share this one `install.py` and wheel. `--extras` and `--exclude` work as for `xeus-env`; exclude packages Pyodide replaces, such as `aiohttp`.

The wheels install with `deps=False`: their dependencies come by name from `--pyproject`, so the wheel must be built from that same project. `--bundled-wheel FILE` (repeatable, `dep_a` above) adds a wheel already in `DIR`, such as a private dependency not on the piplite index; it drops out of the by-name list.

By-name packages already installed in the kernel are skipped, whatever their version: numpy, for instance, loads with matplotlib at kernel startup. Pyodide distribution packages that aren't loaded yet still install from the distribution, so a dependency the project imports but the notebooks don't still works.

### `jl-forge pyodide-dist --out FILE [options]`

Self-hosts Pyodide. By default the Pyodide kernel loads Pyodide and its packages from the jsDelivr CDN at run time, which fails where that CDN is blocked. This writes the distribution the installed kernel loads, pruned to the packages the site uses, and prints its absolute path for `jupyter lite build --pyodide`:

```bash
PYODIDE_DIST=$(jl-forge pyodide-dist --pyproject pyproject.toml --wheels-dir workspace/lite-pyodide/pypi --out workspace/pyodide-dist.tar.bz2)
jupyter lite build ... --pyodide "$PYODIDE_DIST"
```

- **Version**: read from the installed `jupyterlite-pyodide-kernel` (`0.29.0` for kernel 0.7.0, `314.0.6` for 0.8.6), so the distribution always matches the kernel. Run it in the Pyodide build venv, or pass `--version`.
- **Download**: the full release (about 340 MB) from GitHub, once, into `--cache-dir` (default `~/.cache/jl-forge/pyodide`).
- **Kept packages**: the kernel's startup packages (IPython, matplotlib, micropip, ...), the project's dependencies from `--pyproject`/`--extras`, the dependencies of the wheels `pyodide-wheels` bundled in `--wheels-dir DIR` (pass its `--out-dir`, e.g. urllib3 for a bundled botocore; extras the project asks for, like `botocore[crt]`, count), and `--keep NAME ...`, each with its dependencies from `pyodide-lock.json`. Everything else is left out; the demo's distribution is 23 MB instead of 340 MB. `--no-prune` ships the full release.
- **Output**: a `.tar.bz2` with the upstream top-level `pyodide/` directory, the only form `--pyodide` copies into the site; pass its absolute path, which the command prints.

A notebook that imports a distribution package nobody declared fails in the browser with a `ModuleNotFoundError` and a 404 for its wheel: add it to the project's dependencies or to `--keep`.

### `jl-forge pyodide-wheels --out-dir DIR [options]`

Bundles into the site the wheels piplite would otherwise fetch from PyPI in the browser. Run it in the Pyodide build venv, writing to `<lite-dir>/pypi`, which `jupyter lite build` indexes; piplite then installs them from the site:

```bash
jl-forge pyodide-wheels --pyproject pyproject.toml --out-dir workspace/lite-pyodide/pypi
jupyter lite build --lite-dir workspace/lite-pyodide ...
```

- **What**: `comm`, which the kernel installs at startup, the requirements from `--pyproject`/`--extras` and `--require REQ ...`, and their dependencies, except packages the Pyodide distribution or the kernel's own index (piplite, its `ipykernel` and `widgetsnbextension` stand-ins) provides. Markers are evaluated for Pyodide's Python. For the demo: ipywidgets, jupyterlab_widgets and comm.
- **Where from**: the newest pure-Python wheel at the version [uv](https://docs.astral.sh/uv/) solved (see below), from PyPI's JSON API, cached in `--cache-dir` (default `~/.cache/jl-forge`). Repeat `--index-url` for secondary indexes with the same API, such as an intranet mirror: they are tried in order. A package with no pure-Python wheel that the distribution lacks can't run in Pyodide: the command fails.
- **Wheels from elsewhere**: `--wheel PATH ...` bundles local wheels, such as packages from a private index downloaded with pip, and follows their dependencies.
- **`--strip-requires NAME ...`**: bundles those packages without their dependency metadata, so piplite installs them alone; for packages whose dependencies can't be satisfied in the browser.

**Resolution**: `uv`, which the `pyodide` extra installs (`pip install 'jl-forge[pyodide]'`); without the extra, `uv` 0.7.11 or later must be on `PATH`. It solves all requirements together for Pyodide (`uv pip compile --python-platform wasm32-pyodide2024`, markers for Pyodide's Python), so one version fits every constraint. It uses its own index settings (`UV_INDEX_URL`, `uv.toml`, `pip.conf`), or the `--simple-index-url` URLs (repeatable, the first is the default); give both `--index-url` and `--simple-index-url` for an intranet index. Packages the distribution provides are left out of the solve, and a requirement their version in `pyodide-lock.json` doesn't satisfy (`numpy>=3` against numpy 2.0) fails the command. Incompatible constraints fail it too, with uv's explanation, instead of a broken install. uv's newest Pyodide target is Python 3.12's, which only matters for pure-Python wheels, the only kind bundled.

### `jl-forge self-host PUBLIC [--cache-dir DIR]`

Makes the built sites in `PUBLIC` serve the files they still fetch from other hosts:

- **xeus-python**: the conda-to-PyPI name mapping (`prefix-dev/parselmouth`, BSD-3-Clause, about 1 MB) that jupyterlite-xeus fetches at kernel start. Its URL is rewritten to a relative one, and the file placed next to every page and the kernel worker, which each resolve it against their own directory; `jl-forge dedup` then stores the copies once.
- **Voici**: Font Awesome 5.15.4 (CC-BY-4.0, OFL-1.1 and MIT; CSS, `woff2`/`woff` fonts and `LICENSE.txt`), linked from Voici pages.

Run it after `jupyter lite build` and before `dedup`; running it again changes nothing. The mapping copies are 1 MB each, stored once by `dedup` except on GitHub Pages. With `pyodide-dist` and `pyodide-wheels` too, the demo's pages make no request to other hosts.

### `jl-forge dedup PUBLIC`

Replaces files with identical content under `PUBLIC` by hardlinks to one copy. Two sites built side by side share most of their JupyterLab bundles and source maps, and `self-host` places copies of the mapping: in the demo, 1,104 files, 217 MB down to 138 MB on disk.

Run it last: a later step editing a file in place would change all its linked copies.

Where it helps depends on how the site is uploaded:

| Host | Hardlinked files in the uploaded site |
|:--|:--|
| GitLab Pages | Stored once (GNU tar's default) |
| GitHub Pages | Stored in full: `actions/upload-pages-artifact` archives with `--hard-dereference` |
| Local disk, CI caches | Stored once |

### `jl-forge size PUBLIC [--max SIZE] [--links-once]`

Prints the size of `PUBLIC` counting every file in full, and counting hardlinked files once. With `--max` (e.g. `1G`, `1000M`; powers of 1024, as with `du`), it fails above the limit, measured in full, as GitHub Pages stores it, or with `--links-once` as GitLab Pages stores it:

```bash
jl-forge size workspace/public --max 1G                 # GitHub Pages
jl-forge size workspace/public --max 1000M --links-once # GitLab Pages artifact limit
```

### `jl-forge urls PUBLIC [--port PORT]`

Prints the command serving `PUBLIC` locally, then a URL for each notebook of each site found in `PUBLIC` (the directory itself or its subdirectories containing `jupyter-lite.json`), per app built: `lab`, `notebooks`, and Voici render pages when present.

```bash
$ jl-forge urls workspace/public
Serve: python -m http.server 8000 --directory workspace/public
http://localhost:8000/
http://localhost:8000/pyodide/lab/index.html?path=demo.ipynb
http://localhost:8000/xeus/lab/index.html?path=demo.ipynb
...
```

## Dependency Handling

Both kernels read the same `pyproject.toml`:

- Names are normalized (`My_Pkg` → `my-pkg`).
- A package listed several times keeps the intersection of its constraints: `tqdm>=4` and `tqdm<5` become `tqdm<5,>=4`.
- Environment markers are evaluated for the browser (`sys_platform == "emscripten"`), so `pywin32; sys_platform == "win32"` is dropped.
- Requirement extras (`pkg[extra]`) are dropped; conda and piplite don't resolve them.

Specs are passed unchanged to conda and piplite. Use constraints both understand: `==`, `>=`, `<`, `!=`.

## Python API

```python
from pathlib import Path
from jl_forge import dependencies, notebooks, pyodide, xeus

project = dependencies.load_project(Path("pyproject.toml"))
specs = dependencies.to_specs(dependencies.collect_requirements(project, extras=["lab"], baseline=xeus.XEUS_RUNTIME))

prefix = xeus.create_env(Path("workspace/xeus"), specs, micromamba=True)
mounts = xeus.mount(Path("src/mypkg"), prefix)

nb = notebooks.read(Path("demo.ipynb"))
notebooks.prepend_to_first_code_cell(notebooks.strip(nb), pyodide.INSTALL_LINE)
notebooks.write(Path("demo.ipynb"), nb)
```

`jl_forge.cli.reset_workspace(workspace, root)` and `jl_forge.cli.site_urls(public, base_url)` are the functions behind `clean` and `urls`.

## Compatibility Guarantees

- **Commands** are the stable interface: command names, options, exit codes, and what they print to stdout, which build scripts capture (e.g. `$(jl-forge xeus-env ...)`).
- **Public Python API** is only what the [Python API](#python-api) section shows:
  - `dependencies.load_project`, `dependencies.collect_requirements`, `dependencies.to_specs`
  - `notebooks.read`, `notebooks.write`, `notebooks.strip`, `notebooks.prepend_to_first_code_cell`
  - `xeus.create_env`, `xeus.mount`, `xeus.XEUS_RUNTIME`
  - `pyodide.INSTALL_LINE`
  - `cli.reset_workspace`, `cli.site_urls`
- **Everything else is internal**, including the `wheels`, `selfhost`, `cache` and `artifact` modules and the other functions of the modules above. It can change in any release.

Before 1.0, a breaking change to the commands or the public API comes only in a minor release (0.x → 0.y) and is listed in the release notes. From 1.0, it needs a major release. Supported Python, kernel and app versions are in [COMPATIBILITY.md](COMPATIBILITY.md).

So before 1.0, bound the minor version in your dependencies (`jl-forge>=0.8,<0.9`; `~=0.8` would also accept 0.9) and raise the bound when you've read the release notes. An open `jl-forge>=0.8` lets a breaking release reach your build unannounced. To see a break before you upgrade, build your site on a schedule with the development jl-forge, as this repository's [consumer builds](../.github/workflows/consumers.yml) do for the projects that use it.

## Complete Build Script

[`examples/demo/build.sh`](../examples/demo/build.sh) builds both sites from one project. Its outline:

```bash
jl-forge clean workspace

# xeus-python, from a venv with jupyterlite-core + jupyterlite-xeus
jl-forge notebooks workspace/content-xeus --strip
XEUS_PREFIX=$(jl-forge xeus-env --micromamba --cache-dir ~/.cache/jl-forge/xeus --pyproject pyproject.toml)
jupyter lite build --contents "$PWD/workspace/content-xeus" --output-dir workspace/public/xeus \
  --XeusAddon.prefix="$XEUS_PREFIX" \
  --XeusAddon.empack_config="$(jl-forge xeus-pack-config --out workspace/empack.yml)" \
  --XeusAddon.mount_jupyterlite_content=True \
  --XeusAddon.mounts="$(jl-forge xeus-mount src/mypkg --prefix "$XEUS_PREFIX")"   # only if notebooks import your own package

# Pyodide, from a venv with jupyterlite-core + jupyterlite-pyodide-kernel
# only if notebooks import your own package: its wheel, install.py and install line (else just --strip)
uv build --wheel --out-dir workspace/content-pyodide .
jl-forge pyodide-install --pyproject pyproject.toml --package-name mypkg --wheel-dir workspace/content-pyodide
jl-forge notebooks workspace/content-pyodide --strip --pyodide-install
jl-forge pyodide-wheels --pyproject pyproject.toml --out-dir workspace/lite-pyodide/pypi
jupyter lite build --lite-dir workspace/lite-pyodide --contents "$PWD/workspace/content-pyodide" --output-dir workspace/public/pyodide \
  --pyodide "$(jl-forge pyodide-dist --pyproject pyproject.toml --wheels-dir workspace/lite-pyodide/pypi --out workspace/pyodide-dist.tar.bz2)"

jl-forge self-host workspace/public
jl-forge dedup workspace/public
jl-forge size workspace/public --max 1G
jl-forge urls workspace/public
```

Application-specific steps (credentials, model files) stay in your script.

## Voici Dashboards

[Voici](https://github.com/voila-dashboards/voici) renders each notebook as a dashboard page, run in the browser by the site's kernel. jl-forge needs nothing specific: install `voici-core` in the build venv and list `--apps voici` in `jupyter lite build`. [VOICI.md](VOICI.md) has the setup, the version constraints and the known problems.
